# Model selection: the Agent's ACP `model` config option, switched with `session/set_config_option`

Users want to pick the model when creating a Session and change it later from the chat, for every Provider. Each Provider has its own catalog (Claude Code offers `default`/`sonnet`/`opus[1m]`/`haiku`-style aliases that change with releases; Devin returns a several-hundred-entry, account-dependent list of Claude, GPT, Gemini, DeepSeek, GLM, Grok, Kimi, SWE and fusion variants), so a list hard-coded in Sessionboxer would be wrong within weeks.

Probes on this VM established: both Agents advertise a `select` config option with `category: "model"` (id `model`) over ACP; Claude in the `session/new`/`session/load` result, Devin in a `config_option_update` notification shortly after `session/new`; both accept `session/set_config_option { configId: "model", value }` and return the updated options; the switch takes effect for the next prompt without restarting the Agent; a switch during an active turn is accepted but the running turn keeps its model (Claude answered as Sonnet after being switched to Haiku mid-turn, and only the next turn ran as Haiku).

## Considered Options

- Command-line model flags (`claude --model`, Devin config) at Agent start (rejected): would need the same restart-in-place as MCP toggles for every change, is Provider-specific, and does not give us the list.
- A model list maintained in Sessionboxer (rejected): stale by construction, and wrong per account for Devin.
- The ACP `model` config option, read from the Agent and switched with `session/set_config_option` (chosen): dynamic, Provider-agnostic, no restart. A change during a turn is deferred to the turn's end so the UI never claims a model the running turn does not use.

## Consequences

- Protocol: `ModelOption { value, name, description, group }` (normalized from ACP `SessionConfigSelectOption`/`SessionConfigSelectGroup`); `Session.model` (the chosen value, `null` = the Provider's default) and `Session.modelPending`; `model` on create/update requests; `DaemonStatus.models/model/modelPending`; `_sessionboxer/model/set` RPC returning `{ applied }`; `model_changed { model, name }` event; `models { provider, models }` broadcast; `GET /api/models` returning `ProviderModels` (`Record<Provider, ModelOption[]>`).
- Daemon: `captureConfigOptions()` runs on `session/new`, `session/load`, `set_config_option` results and `config_option_update` notifications and remembers the option id, the flattened values (with their group label) and the current value. `setModel()` applies right away when idle (serialized on one promise chain, after any pending MCP restart) or records the value as pending and applies it right after `turn_ended`; the requested model is re-applied after every Agent start (`session/load` on resume or after an MCP restart), so it survives Stop/Resume even though Devin reloads with its default. A value the Agent does not offer fails with an `agent_error` in the transcript and the Daemon's stored choice reverts to what the Agent runs; `config_option_update` is not treated as a transcript update.
- Control Plane: `sessions.model`/`model_pending` columns; `provider_models` table caching the last list per Provider so New Session can offer it before any Sandbox exists (updated from `DaemonStatus.models`, broadcast on change); `pushModel()` after the MCP set on every Daemon connect and on `PATCH /api/sessions/:id { model }`; status sync copies `model`/`modelPending` back from the Daemon. Forks copy the origin's model. A Daemon without the RPC gives the same 502 Stop/Resume hint as MCP.
- Web: `ModelSelect` in New Session (per Provider, resets when the Provider changes, "Provider default" entry, empty-catalog hint) and compact in the composer footer; ACP groups render as `<optgroup>`, and a flat list above 24 entries is grouped by the first token of the value (Devin's `claude-…`, `gpt-…`, `fusion-…`). An unknown persisted value stays selectable rather than being dropped. The composer picker is hidden for a Provider with no catalog and no chosen model, so a Provider without a `model` option is unaffected. Pending state shows next to the picker; `model_changed` renders as a `Model now: …` marker. CLI: `sessionboxer new --model <id>`.
- Not done: resetting an existing Session back to the Provider default (the request schema only takes a non-empty model); descriptions per model are shown in New Session and as tooltips in the composer.

## Verified (M10)

Through the REST API against live Sandboxes: Claude catalog stored after the first Session start; create with `model: "haiku"` answered as `claude-haiku-4-5-20251001`; idle switch `haiku → sonnet` emitted `model_changed` and the next answer named Sonnet; a switch during a 300-line turn set `modelPending: true`, the turn finished as Sonnet and `model_changed` to Haiku fired right after `turn_ended`; Stop/Resume kept Haiku. Devin: 385-entry catalog arrived via `config_option_update` and reached `/api/models`; `swe-2-high → swe-2-medium` applied idle; Stop/Resume re-applied `swe-2-medium` (Devin had reloaded as `swe-2-high`); an unknown value produced one `agent_error` and the Session reverted to the running model. Browser check: New Session picker per Provider with Devin grouped by family; composer picker shows the current model.
