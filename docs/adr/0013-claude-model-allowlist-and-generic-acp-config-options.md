# Claude models via the `availableModels` allowlist; other Agent settings as generic ACP config options

Two gaps in the model picker (ADR-0011): Claude Code's list stopped at Sonnet/Opus/Haiku although the account has Fable, and Devin's list had no Lite/Normal/Ultra, the tiers Devin Cloud shows.

Probes in a live Sandbox: `claude --model fable` works (answers as `claude-fable-5-1`), but `claude-agent-acp` (0.77 and 0.78) offers only the aliases the Claude Agent SDK hands it and rejects others (`Invalid value for config option model: fable`); adding `"availableModels": ["opus", "sonnet", "haiku", "fable"]` to `~/.claude/settings.json` in the Sandbox makes Fable appear in the ACP `model` option and work. Claude also advertises two more `select` config options we did not show: `effort` (`default`, `low`, `medium`, `high`, `xhigh`, `max`) and `fast` (`on`, `off`), and hides both while Fable is selected (the adapter does not know Fable's capabilities). `devin acp` advertises only the permission mode and its model catalog; Lite/Normal/Ultra are Devin Cloud session tiers with no CLI/ACP counterpart, and Cognition does not document a mapping to model + effort, so we do not invent one.

## Considered Options

- Bake `availableModels` into the image (rejected alone): fixed at build time; users with other aliases would rebuild.
- A Settings list of Claude model aliases written into the Sandbox's Claude settings before the Agent starts (chosen), default `opus, sonnet, haiku, fable`. Changing it restarts an idle Agent in place (like an MCP toggle) so the picker updates; during a turn it waits for the turn's end.
- Hard-coded Effort/Fast selectors for Claude (rejected): the adapter hides them per model and their values change with releases.
- Generic handling of every ACP `select` config option that is not the model (chosen): the Daemon reports them, the UI renders one picker per option with the Agent's labels, and sends the exact ACP value with `session/set_config_option`. Options appear only when the Agent advertises them, so Devin (none today) shows nothing and no Cloud-tier lookalike is fabricated.
- Mapping Devin Cloud tiers to model/effort combinations (rejected): unverified.

## Consequences

- Protocol: `AgentOption { id, name, description, category, choices: OptionChoice[] }`, `OptionValues` (`Record<optionId, value>`), `ProviderOptions`; `Session.options` (requested values), `optionsPending`, `availableOptions` (what the Agent offers with the current model); `options` on create/update requests; `Settings.claudeModels` (`DEFAULT_CLAUDE_MODELS`); `DaemonStatus.options/optionValues/optionsPending`; `_sessionboxer/option/set { options, lenient }` and `_sessionboxer/claude-models/set { models }` RPCs; `option_changed` event; `options { provider, options }` broadcast; `GET /api/options`.
- Daemon: `ClaudeSettings` rewrites only `availableModels` in `~/.claude/settings.json` (the rest of the file, e.g. `permissions`, is preserved) before each Claude spawn; a changed list restarts the Agent in place when idle, or after the turn. `captureConfigOptions()` keeps the non-model `select` options and their current values. `setOptions()` has the same timing as `setModel()` (immediate when idle, pending during a turn, serialized on the same chain); it is *strict* for a user's change (an option or value the Agent does not offer fails with an `agent_error` and the requested value rolls back) and *lenient* when the Control Plane restores stored values after a connect (unavailable ones are skipped but kept, so `effort=high` chosen under Opus is re-applied when switching back from Fable). Requested options are re-applied after model switches, restarts, `session/load` and forks, without transcript markers in those cases (`announce = false`); markers only mark a user's change taking effect.
- Control Plane: `sessions.options/options_pending/available_options` columns; `provider_options` cache (merged: an option seen once stays in the New Session list even if the last model hid it); push order on connect is MCP, then model, then options; `PUT /api/settings { claudeModels }` pushes the allowlist to every running Claude Session (a Daemon without the RPC is logged and skipped; option changes on such a Daemon return the 502 Stop/Resume hint). Forks copy the requested values.
- Web: `OptionSelects` renders a `<select>` per advertised option next to the model picker in New Session (from the Provider cache, with an "Agent default" entry) and in the composer footer (from the Session's live `availableOptions` while running, so Fast mode disappears under Fable); pending state and `Effort now: …` / `Fast mode now: …` markers. Settings gets **Claude model aliases** with an explanation that it configures `availableModels` and holds no secrets. CLI: `--option effort=high` (repeatable).
- Not done: Devin Cloud tiers (nothing to select); resetting an option back to "Agent default" on a running Session (only at creation).

## Verified (M11)

Live Sandboxes over the REST API: a new Session with `model: "fable"` started with the allowlist written (`claude availableModels: opus, sonnet, haiku, fable`), ran as Fable and advertised no Effort/Fast; a stored `effort=high` was skipped leniently and then applied on switching to Opus (`option effort default -> high`), where `/api/options` cached `effort` + `fast`; `fast=on` applied idle; `effort=medium` requested during a 20 s turn set `optionsPending: true` and applied right after `turn_ended`; switching back to Fable hid both options and Stop/Resume restored Opus/`effort=medium`/`fast=on` without markers. Changing the Settings aliases to add `opusplan` restarted the idle Agent in place and the picker listed it. Devin Session resumed with its 385-entry catalog, no options, `/api/options` empty for Devin. Browser check of the composer: Model, Effort and Fast mode pickers with the current values.
