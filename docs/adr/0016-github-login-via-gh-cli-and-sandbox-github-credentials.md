# GitHub login through the GitHub CLI, downloaded on demand, and GitHub credentials inside the Sandbox

The GitHub connector (ADR-0014) logs in through Sessionboxer's own OAuth App. That works for personal repositories but not for organizations with "third-party application access restrictions": tokens minted by an unapproved OAuth App cannot see the organization's private repositories, while the same user with `gh` can, because GitHub's first-party apps (GitHub CLI, Desktop, VS Code) are exempt. Asking every organization owner to approve "Sessionboxer" is not an option for a local tool, and creating a PAT by hand was rejected as bad UX. A probe confirmed GitHub's remote MCP server accepts any GitHub token as the Bearer header, so the question is only *which app mints the token*.

The second half of the request was for the agent to push commits, draft pull requests and read PR discussions from inside the box: the MCP covers PR reading/creation, but `git push` needs credentials in the Sandbox, which had none.

## Considered Options

- Org owner approval of the OAuth App (rejected): external dependency per organization.
- Classic PAT pasted on the card (rejected): the user explicitly did not want to create tokens by hand.
- A GitHub App installation (rejected): still needs an org admin to install it.
- **Borrow GitHub CLI's login (chosen)**: the Control Plane runs `gh auth login --web` (device flow, `gh` prints a `XXXX-XXXX` code and `github.com/login/device`, polls GitHub itself) with a private `GH_CONFIG_DIR=~/.sessionboxer/gh`, reads the token back with `gh auth token`, the account with `gh api user`, logs the private config out again and stores the token as the entry's secret `Authorization` header exactly like the OAuth-App path. The user's own `gh` configuration is never touched. Shortcut: when the user's `gh` (default config) is already logged in, the dialog offers **Use my gh login as @account** (`gh auth status` to list, `gh auth token --user` to read); one click, no browser step.
- When `gh` is missing on the machine: **download the official release on first use (chosen)** rather than vendoring 40 MB per platform in the repo. Pinned version (`SESSIONBOXER_GH_VERSION` overrides), asset picked by OS/arch (`linux`/`macOS`/`windows` × `amd64`/`arm64`), SHA-256 verified against the release's `checksums.txt` before anything runs, installed to `~/.sessionboxer/bin`. Linux tarballs are unpacked in-process (`tar-stream` + zlib), the macOS/Windows zips with the bundled bsdtar. The GitHub REST API is not used (anonymous rate limits); release download URLs are direct.
- An MCP server wrapping `gh` (deferred): the remote GitHub MCP already lists the PR/issue/repo tools, and a wrapper would need proxying and renaming ~100 tools. Instead the box gets the real `gh` and git credentials, so "everything gh can do" is available in the shell under the same per-Session switch.
- How the Sandbox gets credentials: **`gh`'s own `hosts.yml` on tmpfs (chosen)** over a git credential store or `GH_TOKEN` in process environments. The image sets `GH_CONFIG_DIR=/dev/shm/sessionboxer/gh` and `git config --system credential.https://github.com.helper '!gh auth git-credential'`; the Daemon writes `hosts.yml` (`users:` map, first entry active) whenever the Control Plane sends the enabled connector tokens, and deletes it when none is enabled. `gh` re-reads the file on every invocation, so the change is instant for the agent's shell and the Terminal pane with no restart, and no process environment has to be re-created. tmpfs means Snapshots and stopped containers never contain the token.

## Consequences

- Protocol: `ConnectorVia = gh | gh-existing | app`, `ConnectorStartRequest.via` (default `gh`) and `.account`, `ConnectorFlow.via`, `GhCliStatus { available, version, logins }`, `BoxCredential { kind, account, token }`, `DaemonMcpSetParams.credentials`.
- Control Plane: `gh-cli.ts` (`findGh`, `ensureGh`, `hostLogins`, `hostToken`, `deviceLogin`); `Connectors.start()` branches on `via`; `GET /api/connectors/github/gh` for the dialog; `resolveBoxCredentials()` turns enabled connector entries into `BoxCredential`s sent alongside the MCP set in `pushMcpServers()` (create, resume, toggle). `gh`'s own login asks for `repo, read:org, gist, workflow, read:user, user:email`. Tokens never appear in flows, public settings or logs (verified by a fake-`gh` test in `.local/`).
- Sandbox: `GhCredentials` in the Daemon writes/removes `hosts.yml`; image rebuild needed for the env and the git helper. `gh` was already installed.
- Web: `ConnectorDialog` shows **Log in with GitHub** (gh), one **Use my gh login as @x** per host account, and **Log in with the Sessionboxer OAuth App**; the primary button says "Downloading GitHub CLI…" when none is installed.
- Not done: SSH remotes in the box; `gh` on GitHub Enterprise hosts; refresh of the private-download version (re-download happens only when `~/.sessionboxer/bin/gh` is deleted); a `gh`-wrapping MCP.
