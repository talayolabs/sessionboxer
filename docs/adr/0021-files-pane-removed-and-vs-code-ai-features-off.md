# Files pane removed; VS Code's AI features switched off in the Sandbox

The Files pane (tree + Monaco editor, ADR-0006/0017/0018) was the way to look at and edit Workspace files before VS Code ran in the Sandbox (ADR-0019). With the Code pane, it was a second, weaker editor with its own file-tree, watcher and JSON-RPC surface to keep in step, and it shipped Monaco (and its five web workers) in the bundle for that alone. Separately, the VS Code that runs in the box shows its built-in AI affordances (Copilot status item, "Toggle Chat", the Chat view and the many `Chat:` commands) even though no AI extension is installed there, which reads as a second agent next to the one in the chat.

## Decisions

### Files pane removed

- Removed: the `Files` pane and `Files.tsx`, the Monaco setup (`monaco.ts`, `monaco-editor`, `@monaco-editor/react`), the `fsList` / `fsRead` / `fsWrite` API methods and REST routes (`/api/sessions/:id/fs`, `/fs/file`), the `_sessionboxer/fs/list|read|write` Daemon RPCs, the chokidar Workspace watcher with its `_sessionboxer/fs/changed` notification and the `fs_changed` UI broadcast, and the `FsEntry` / `FsListResult` / `FsReadResult` / `FsWrite*` / `FsChange*` protocol types.
- Kept, because the chat depends on them: `GET /fs/raw` on the Daemon (proxied as `/api/sessions/:id/fs/raw`) with its lexical + realpath containment (`WorkspaceFs.raw`, now the class's only job), the `AttachmentCard` / `DocumentView` / `Markdown` / `Mermaid` components that render files named in agent replies, and the manifest + tar RPCs behind **Pull to folder…** (ADR-0020).
- Editing files by hand is the Code pane's job; the Terminal pane covers the rest. `localStorage` values of `files` for the pane selection fall back to Desktop.

### VS Code AI features off, no Get Started, no Extensions icon / remote indicator

- The Sandbox defaults for the workbench move from the Machine settings file (`~/.openvscode-server/data/Machine/settings.json`, ADR-0019) to `images/sandbox/openvscode-defaults.js`: a classic script the Dockerfile links from `workbench.html` (`{{WORKBENCH_WEB_BASE_URL}}/out/vs/code/browser/workbench/sessionboxer.js`, served by the server's own static route) that adds the defaults to the page's `vscode-workbench-web-configuration` as `configurationDefaults` before `workbench.js` reads it. Reason: Machine settings arrive from the server after the workbench has decided its startup editor, so on a fresh browser profile `workbench.startupEditor: none` lost the race and the "Setup VS Code Web" walkthrough opened anyway (reproduced: 1 of 3 fresh loads). `configurationDefaults` are in place before the first paint, and being defaults the user can still override any of them in the box's settings. Server-side `User/settings.json` is not read at all by the web client (its user settings live in the browser), and `product.json` is inlined in the web bundle, so neither was an option.
- Defaults: the previous Machine settings (telemetry off, `workbench.startupEditor: none`, tips off, extension auto-update off, auto-save, `git.openRepositoryInParentFolders`), plus `workbench.welcomePage.walkthroughs.openOnInstall: false` (the walkthrough), `chat.disableAIFeatures: true` (VS Code's own switch: hides the Chat view, the title-bar chat button, the Copilot status item and the chat/agent commands), `chat.agent.enabled: false`, `editor.inlineSuggest.enabled: false` (no ghost-text completions if a provider ever gets installed) and `workbench.settings.showAISearchToggle: false`. Defaults rather than a locked policy: the intent is a clean editor, not a prohibition. The one remaining `Chat:` command is VS Code's "Use AI Features with Copilot for free…" re-enable entry point.
- `images/sandbox/openvscode-workbench.css`, linked the same way, hides the Extensions item in the activity bar (`Ctrl+Shift+X` still opens the view; Open VSX stays configured) and the `status.host` remote indicator in the status bar with its menu, since everything in the pane is remote by construction and the Code pane's own toolbar already says so. VS Code has no setting for either (hiding them by hand is stored in the browser's storage, per browser).
- The Dockerfile's `sed` on `workbench.html` is followed by a `grep` so a server upgrade that changes the template fails the build instead of silently dropping the tweaks.
- Verified on the rebuilt image in fresh browser contexts: 4/4 first loads open with no editor; no Extensions icon, no remote indicator; "Toggle Chat" and "Copilot status" absent and one `Chat:` command in the palette, versus both items and the full `Chat …` command list with the defaults removed.

## Consequences

- Smaller web bundle (Monaco and its workers gone), one fewer dependency in the Daemon (chokidar), no filesystem watcher running in every Sandbox.
- No in-app file editing outside VS Code; Markdown files still render in the chat when the agent names them, but there is no Preview/Edit toggle for arbitrary `.md` files any more (open them in the Code pane).
- ADR-0017/0018/0019 mention the Files pane and the Machine settings file where they existed at the time; they are left as written.
