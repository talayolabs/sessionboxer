# Standing instructions for the Agent, as a system prompt where the Agent takes one and as a first-prompt prefix otherwise

Until now the only standing text the Agent got from Sessionboxer was the Sandbox briefing, installed as `~/.claude/CLAUDE.md` in the box (read by Claude Code as user memory, by Devin as an always-on rule). Whether and when such files are read is up to the Agent's implementation (reports of them being skipped exist), and users had no place to add rules of their own that hold for every Session, such as "no agent attribution in commits" or "test the change on the desktop and record it". The prompt itself went to the Agent verbatim (`session/prompt`), and ACP has no system-prompt field.

## Decisions

- `Settings.instructions` (config.json, editable in Settings, `DEFAULT_INSTRUCTIONS` shipped) is the default text for new Sessions; `CreateSessionRequest.instructions` overrides it for one Session (omitted: the Settings text, `""`: none) and is stored as `Session.instructions`, immutable after creation (the Agent has it from its first start; changing it later would mean different rules in one conversation). Forks copy the origin's text. 20 000 characters at most. Web: textarea in Settings (reset to the shipped default), textarea in New Session prefilled with the Settings text (reset to it), read-only **Instructions** dialog in the Session header; CLI: `--instructions <text|@file>`.
- The Control Plane hands the text to the box as `SESSIONBOXER_INSTRUCTIONS` in the container environment, next to the provider secrets; like them it is never written into the image, and `docker commit` strips the environment, so snapshots do not carry it (the forked Session sets it again from its own row).
- Delivery depends on the Provider (`instructionsDelivery(provider)` in the protocol, so the UI can say which applies):
  - **`system-prompt`** (Claude Code): `claude-agent-acp` reads `_meta.systemPrompt.append` on `session/new` and `session/load` and passes it to the SDK's `systemPrompt: { type: "preset", preset: "claude_code", append }`, i.e. the text becomes part of Claude Code's system prompt. The Daemon adds that `_meta` to every `session/new`, `session/load` (Resume, branch switch) and the `session/load` after a `session/fork` (rewind), so it holds for the whole life of the Session and not only for the first conversation. Verified live: a Session created with a rule the model could not know otherwise ("answer `pineapple` with `MANGO-7731`") follows it on the first prompt, and after Stop → Resume.
  - **`first-prompt`** (Devin): the Devin CLI's ACP server has no system-prompt hook, so the Daemon prepends the text (with a short framing: "Standing instructions from the user for this whole session; follow them in every turn…", then `---`, then the user's message) to the first `session/prompt` of every ACP session it creates for the Session. "First" is tracked in the Daemon's persisted state (`freshSessionIds`: ACP sessions created here that have not been prompted yet), so it survives a Daemon restart and Stop → Resume, and is consumed right before the request is sent; a session obtained through `session/load` or `session/fork` is not fresh (its history already has the prefixed first message). The transcript replay used for rewinds on Agents without `session/fork` gets the same prefix ahead of the replayed conversation. The Control Plane stores and shows the user's text as typed; only the wire message to the Agent is prefixed. Verified live: the rule is followed on the first, second and post-Resume prompt, and after a rewind by replay, with exactly one "instructions prepended" log line.
- The default text (in `packages/protocol`): no agent-authored commit attribution (no `Co-Authored-By`, no "generated with", no Claude/Devin in commit messages or PR text) and, after code changes that can be exercised, run the application, test end to end on the desktop and record the core part with the desktop MCP's `start_recording` / `stop_recording`, handing the user the path so it plays in the chat. Because Claude Code adds its byline itself regardless of instructions, the box's `~/.claude/settings.json` also sets `includeCoAuthoredBy: false`.
- The Sandbox briefing stays as it is: it describes the box (desktop tools, recordings, how to hand files to the user), the instructions carry the user's rules. Both are behavioural guidance to the model, not a security boundary; enforcement in the strict sense would need hooks or a policy on the git side, which this does not attempt.

## Consequences

- Every Session's Agent gets the user's rules in the strongest place the Agent offers, without depending on the Agent picking up a file; per-Session overrides are one field away in New Session.
- Devin's first message of a conversation is longer than what the user typed (visible to the Agent only); a rewind that replays the transcript repeats the prefix once, by design.
- `Session.instructions` can be changed only by creating a new Session (or a fork, which inherits it); a Settings change applies to Sessions created afterwards.
- Existing databases get the `instructions` column through the additive migration (`''` for old Sessions, which therefore have none); the image needs a rebuild for the Daemon and the Claude settings file.
