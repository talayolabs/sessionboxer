# Compaction details: what was dropped and what replaced it, read from the Provider's own records in the Sandbox

The user asked whether the compaction marker in the chat (ADR-0030) could be clicked to see the conversation the agent threw away and the summary it was replaced with. ACP does not carry either: the experimental `compaction_update` has an optional `summary` field that neither claude-agent-acp nor Devin fills, and Devin sends no compaction event at all — its `/compact` produces only a display-only `agent_message_chunk` reading `Context compacted`. Both agents, however, persist exactly what we need inside the Sandbox.

## Decision

**Read the Provider's records on demand, in the Daemon.** A new RPC `_sessionboxer/context/compaction` (`POST /api/sessions/:id/context/compaction`, `CompactionDetailsRequest` → `CompactionDetails`) reads the agent's own store for the current ACP session and returns, for the requested compaction, the *messages compacted away* (normalised to `{role, text, truncated, kept}`), the *summary it became*, the trigger and token counts the Provider recorded, the file it came from and a note about anything it could not tell. Nothing is copied, mirrored or stored by Sessionboxer; the details exist only while the Sandbox runs (the Control Plane answers 409 for a stopped Sandbox) and are read when the dialog opens.

**Claude Code** (`packages/sandbox-daemon/src/compactions.ts`, `claudeCompactions`): the transcript `~/.claude/projects/<cwd with non-alphanumerics as ->/<acpSessionId>.jsonl` holds a `system/compact_boundary` line per compaction with `compactMetadata` (`trigger`, `preTokens`, `postTokens`, `durationMs`, and `preservedMessages.uuids` — the messages carried into the new window verbatim), followed by the summary as a user-role line flagged `isCompactSummary`. The reader walks the file once: every non-sidechain, non-meta message since the previous boundary is a "before" message (tool uses become `Tool <name>(args)` text, tool results `role: tool`, `<local-command-*>` wrappers are unwrapped, thinking blocks are dropped), the preserved uuids are flagged `kept`, and the summary plus the kept messages seed the next window so a second compaction shows what its own window contained.

**Devin** (`devinCompactions`): `~/.local/share/devin/cli/sessions.db` (SQLite, WAL; opened read-only with `node:sqlite`) stores the conversation as `message_nodes`. A compaction is a system node whose metadata carries `extensions["devin-rs/summary"]` or `summarized_from`; the compacted conversation is the node chain from the parent of the `summarized_from` node back to the root (fallback: the `chisel/conversation_history` messages embedded in the node), and the summary is the node's own text, which also names the `summaries/history_*.md` file Devin wrote. Devin records the window size before the compaction (the last `usage` on the chain) but not after it, nor the trigger; the response says so in `note` rather than inventing values.

**The marker is a button** once the compaction is completed. Its `index` counts completed compactions in the transcript; the request carries the marker's `preTokens` / `postTokens` / `trigger` too, so the Daemon matches the Provider's record by metadata when it has more or fewer records than we saw (a `note` tells when the match was by proximity). The dialog (`apps/web/src/CompactionDialog.tsx`) shows the facts line, the two columns *Compacted away* (role labels, `kept verbatim` in green for Claude, `cut` for messages the Daemon bounded, More/Less for long ones) and *Summary it became* (rendered Markdown), the source line, and a clear error for a stopped Sandbox, a missing store or a Provider without a record.

**Devin's `Context compacted` display message is folded into a compaction** (`isDevinCompactedNotice` in `context-model.ts`): it becomes a marker with `preTokens` set to the last usage seen and no trigger or post size, so the count next to the gauge and the marker exist for Devin at all, and the notice is no longer rendered as an agent bubble. On the way we also fixed the status race the same `/compact` exposed: Devin's `turn_ended` arrives before the `session/prompt` request returns, so the Control Plane's "now running" write came after the "idle" write and left the Session stuck; `SessionManager` now counts turn ends and sets `running` only if none arrived during the prompt request.

## Considered Options

- **Have the agent tell us** (ask it to paste the summary): a prompt round, an inexact answer, and no access to what was dropped.
- **Mirror the Provider stores into Sessionboxer's DB** (rejected for now): survives Stop and Delete-and-fork, but duplicates the agent's memory in a second place, needs redaction rules of its own and a migration; reading on demand is one RPC and zero state. Can be added later if stopped Sessions need it.
- **Fill `compaction_update.summary` upstream** (deferred): the right long-term home; the readers above stay useful for `preservedMessages` and for Devin either way.
- **Read the stores from the Control Plane** (rejected): the files are in the Sandbox's home; only the Daemon has them, and it already speaks for the Agent.
- **Show the raw JSONL / SQLite rows** (rejected): the point is to read the conversation, not the format; both stores are normalised to one message shape.

## Consequences

- One Daemon RPC, one REST route, no image rebuild (Node 22's `node:sqlite` prints an experimental warning once in the Daemon log). Stop → Resume existing Sessions to get the new Daemon.
- Messages are bounded (6k chars each, 400 per compaction, 256 MB files); bounded messages are flagged `truncated` and the note says so. Claude's `/context` exchanges that Sessionboxer sends show up among the compacted messages, because they were in the agent's window.
- The readers only ever open the two known paths under the agent's home for the current ACP session id; no secrets are in those files beyond what the conversation itself contained, and they are shown to the same user who had the conversation.
- Devin's details rest on undocumented store internals (`summarized_from`, `devin-rs/summary`, `chisel/conversation_history`) and on `/compact`'s display message; an automatic Devin compaction that emits neither would go unmarked. When they change, the dialog degrades to "no record", not to wrong content.
