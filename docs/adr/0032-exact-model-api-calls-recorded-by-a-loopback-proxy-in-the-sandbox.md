# Exact model API calls recorded by a loopback proxy in the Sandbox, chained in front of the configured base URL

The user wanted a label on each agent bubble saying "this came out of a model call", and, on click, *everything* that was sent to the model and what came back — all the bytes — plus the guarantee that a company Claude proxy set through `ANTHROPIC_BASE_URL` keeps working: `Claude Code → our recorder → company proxy → Anthropic`. The research (docs/research/context-composition-and-inspection.md) established that Claude Code honours `ANTHROPIC_BASE_URL` even with the OAuth token, and that Devin's CLI sends Cognition an RPC with the new message and a conversation reference, not a model request, so the exact bytes exist inside the Sandbox for Claude only.

## Decision

**A loopback reverse proxy in the Daemon, opt-in per Session, in front of whatever base URL the Sandbox was given.** `packages/sandbox-daemon/src/llm-inspector.ts` listens on `127.0.0.1:7200` (`LLM_INSPECTOR_PORT`) and forwards every request unchanged (method, path, query, body, all headers but hop-by-hop ones; `Host` set to the upstream) to the *upstream*: the Daemon's own `ANTHROPIC_BASE_URL`, or `https://api.anthropic.com` (`ANTHROPIC_DEFAULT_BASE_URL`) when none is set. Responses stream back chunk by chunk as they arrive, so SSE latency is untouched. Only the **Agent child process** gets `ANTHROPIC_BASE_URL=http://127.0.0.1:7200` (`AgentManager.setAgentEnv`, folded into the spawn environment and the start key); the Daemon's environment keeps the real URL, and with inspection off the Agent is spawned without the override and talks to the configured URL directly — no hop at all. Upstream TLS uses Node's root store plus the Sandbox's extra CA file (`/usr/local/share/ca-certificates/sessionboxer-extra.crt`, ADR-0015), the same trust the Agent has, so a company proxy with a private CA works with inspection on or off.

**Bodies are recorded, headers never.** For each `/v1/messages` and `/v1/messages/count_tokens` call the proxy keeps the decoded request and response bodies (gzip/deflate/brotli undone for the copy; the wire bytes are forwarded as they were) as `<call-id>.request` / `<call-id>.response` under `<tmpfs>/llm/`, capped at 4 MB each (`requestTruncated` / `responseTruncated` say so), for the last 40 calls (`KEEP_BODIES`; older files are removed, the summary stays). Other paths (`HEAD /api/hello` health checks and the like) are forwarded and summarised with zero-byte bodies. Headers are forwarded but never written, logged or returned, so `Authorization`, `x-api-key`, the OAuth bearer and any custom proxy header never leave the hop. The tmpfs dies with the Sandbox: Stop → Resume clears every body.

**One summary event per call, numbered by the Control Plane.** The proxy parses just enough of the bodies to describe the call: kind (`turn` when the request carries tools — a conversation call that produces bubbles; `side` when it does not — Claude naming the session, writing a compaction summary; `count_tokens`; `other`), model, `max_tokens`, `stream`, counts and character sizes of system blocks, tools and messages (`LlmRequestShape`), and from the response (JSON or the `message_start` / `message_delta` SSE events) the message id, stop reason and usage. That `LlmCall` goes out as an `llm_call` Session event through the existing ring/broadcast path; the Control Plane assigns the `ordinal` (`LLM #n`) and stores the summary in the events table like any other event. The summary is emitted one second after the call ends, or when the next call starts, because claude-agent-acp reports a reply's tool calls only after reading the stream to its end; emitting first would pair the label with the wrong bubbles.

**Pairing is done in the browser, backwards.** `labelLlmCall` in `apps/web/src/transcript-model.ts` walks the transcript back from an `llm_call` event over the agent messages, thoughts and tool calls that have no label yet and stamps them with the call, stopping at a user prompt, a turn end or an item already labelled. Only `turn` calls label bubbles; `side`, `count_tokens` and `other` calls are listed in **Context → Model API calls** (`Context.tsx`), a table of every call with kind, model, status, tokens, sizes and duration. The `LLM #n` label is a button positioned over the top-left edge of the first labelled item (`.llm-tab` in `Transcript.tsx`), keyboard-reachable, and opens `LlmCallDialog.tsx`: **Request** / **Response** show the exact decoded body (`GET /api/sessions/:id/llm-calls/:callId` → `LlmCallBody`, read from tmpfs on demand) with byte and char counts, a *pretty* JSON toggle, Copy and Download; **Tree** parses both sides (`llm-model.ts`: settings, system blocks with cache markers, tools with sizes, message blocks; response content and stream events); **Diff** compares against the previous conversation call whose body is still in the Sandbox (settings changed, system blocks, tools added/removed, messages added/changed). Devin Sessions get neither the header toggle nor labels nor the table.

**Toggle in place.** `Session.inspectLlm` (DB column, `PATCH /api/sessions/:id { inspectLlm }`, boot payload) is pushed to the Daemon as `_sessionboxer/llm/inspect/set`; the Daemon starts the proxy on first use and calls `setAgentEnv`, which restarts the Agent with `session/load` when idle (same mechanism as the model allowlist, ADR-0013) or defers to the end of the running turn — `inspectLlmPending` mirrors that in the UI. `_sessionboxer/llm/calls` and `_sessionboxer/llm/call` serve the list (with the ids whose bodies still exist) and a body. A Daemon too old for the RPC answers -32601 and the Control Plane turns that into "Stop and Resume the session to refresh it" when turning inspection *on*.

**Settings show the effective base URL.** `Settings.claudeApi` holds an optional `baseUrl`, `authToken` (`ANTHROPIC_AUTH_TOKEN`) and `apiKey` (`ANTHROPIC_API_KEY`) for company proxies that want their own credential; `PublicSettings.claudeApi` exposes the URL, `authTokenSet` / `apiKeySet` and the *effective* URL with its source — `settings`, the Control Plane's own `ANTHROPIC_BASE_URL` environment variable (`env`), or Anthropic's `default` — so the user can see where the boxes actually send their calls. `providerEnv` injects the URL (host-local `localhost` / `127.0.0.1` rewritten to `host.docker.internal`, as MCP URLs are, ADR-0010) and the credentials into Claude Sandboxes only when they differ from the defaults; they are stripped from snapshots with the other secrets (ADR-0009) and never returned by the API.

## Considered Options

- **Ask the agent to echo its context** (rejected): a prompt round, paraphrase, and no tool schemas or system prompt.
- **Claude Code's transcript JSONL** (rejected as the source): has the conversation but not the system prompt, tool schemas or the exact serialisation; kept for the compaction dialog (ADR-0031).
- **A system-wide proxy (`HTTPS_PROXY`) or iptables redirect** (rejected): would need TLS interception and a CA inside the box, and would catch every process; `ANTHROPIC_BASE_URL` on the Agent process alone is the supported hook and needs no certificate.
- **Record headers too, redacted** (rejected): a redaction list is a promise about names we do not control (company proxies add their own); not recording is a guarantee. The bytes shown are the body Claude Code sent at our hop, which is what the user asked for.
- **Always on, or a global setting** (rejected): the bodies hold every file the agent read, the prompts and the system prompt; per Session, off by default, memory-only, bounded.
- **Store bodies in the Control Plane's DB** (rejected for now): would survive Stop, but keeps sensitive copies outside the box and grows fast (150 kB per call here); the summary rows in the events table cost nothing and are enough for the table.
- **Replace `ANTHROPIC_BASE_URL` for the whole Sandbox** (rejected): the Daemon would lose the upstream to forward to and any other tool in the box would hit the recorder; only the Agent gets the loopback.
- **Devin through `WINDSURF_API_SERVER_URL`** (rejected): verified to be a protobuf RPC carrying the new message and a session token in the body; it is not the model request and showing it as such would be misleading.

## Consequences

- No image rebuild: the proxy is Daemon code (synced into running Sandboxes with the Daemon's `dist`); Stop → Resume existing Sessions to get it. `Settings → Claude API base URL` and credentials apply to Sandboxes created afterwards, like the tokens.
- With inspection on, a call travels one more hop inside the box (`127.0.0.1`, no TLS), streams unchanged; when the proxy fails to start the Daemon logs it and spawns the Agent without the override rather than pointing it at a dead port. When the upstream is unreachable the Agent gets a `502` with `type: sessionboxer_inspector_error` and the summary records the error.
- What is recorded is what Claude Code sent, before any rewriting a company proxy does downstream; the dialog says so.
- The `LLM #n` ordinals are per Session and per branch scope, in arrival order; a call whose summary arrives after the next turn's prompt (very slow tool reporting) would pair with nothing and appear only in the table.
- The parsing of request/response shapes rests on the Messages API's public body format; when it does not match, the call is still recorded with `shape`/`usage` null and the exact bytes are still shown.
