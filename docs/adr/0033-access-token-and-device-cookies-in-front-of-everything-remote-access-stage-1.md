# An access token and device cookies in front of everything the Control Plane serves (remote access, stage 1)

The Control Plane listened on `127.0.0.1:4000` with no authentication at all: anyone who could reach the port had the agents, root in every Sandbox and the GitHub logins. The user wants to run Sessionboxer on a home server, a Raspberry Pi or a VPS and use it from a laptop or a phone on another network. The research (docs/research/remote-access-from-a-phone-or-another-machine.md) settled that the rendezvous the phone and the server both need is an existing product — a Headscale server we host (`tunnel-sessionboxer.talayolabs.com`, repository `talayolabs/sessionboxer-tunnel`), Tailscale, or Cloudflare Tunnel — and that what Sessionboxer itself must gain is a login, a way to log a phone in without typing a 32-character token, protection of the WebSocket upgrades, keepalives, and knowledge of the origin it is reached at. This ADR is that stage; the phone layout and push notifications are later stages.

## Decision

**One access token per Control Plane; browsers exchange it once for a device cookie.** `ensureAccessToken` generates 24 random bytes (32 base64url characters) into `config.json` as `accessToken` at first start; `SESSIONBOXER_ACCESS_TOKEN` in the environment overrides it and then cannot be rotated from the UI (`RemoteAccess.accessTokenSource` says which). `POST /api/auth/login { token, name }` compares in constant time and answers with a **device**: a row in the new `devices` table (id, name, user agent, created / last seen, last address) and a `sessionboxer_device=<id>.<secret>` cookie (8 and 32 random bytes), `HttpOnly; SameSite=Lax; Path=/; Max-Age=1 year`, `Secure` when the request came over HTTPS (directly or, with `SESSIONBOXER_TRUST_PROXY=1`, per `X-Forwarded-Proto`). Only `sha256(secret)` is stored; the browser never holds the token (no `localStorage`, no URL). The name is what the user typed or a description of the user agent (`Safari on iPhone`). A device's `last_seen` / `last_ip` are touched at most once a minute.

**Everything under `/api` goes through the same middleware, HTTP and WebSocket alike.** `Auth.middleware()` runs on the `api` sub-app before any route: it rejects a request whose `Origin` names a host other than the request's `Host` (or `X-Forwarded-Host` when the proxy is trusted, or the host of `SESSIONBOXER_PUBLIC_URL`, for proxies that rewrite `Host`) with 403, authenticates `Authorization: Bearer <token>` (the CLI) or the cookie, and answers 401 `Login required.` otherwise. The only public routes are `GET /health`, `POST /auth/login`, `POST /auth/pair/redeem` and `GET /auth/me` (which returns `{ principal: null }` rather than 401 so the browser can decide between the app and the login screen without a console error). The WebSocket routes — `/api/ws`, terminals, the noVNC Desktop, the VS Code proxy — are Hono routes on the same sub-app, so `upgradeWebSocket` never runs without a principal: an unauthenticated upgrade is a plain 401 before the handshake. Failed logins and pairing redemptions count per client address: 10 in 15 minutes, then 429.

**Pairing: a QR code or link instead of the token.** A logged-in device asks `POST /auth/pair` for a one-time code (16 random bytes as base64url, in memory, 5 minutes, `PAIRING_TTL_MS`) and shows it as `<public URL>/#pair=<code>[&next=<route>]` plus a QR (`qrcode-generator`, rendered as a crisp SVG). The browser that opens it calls `POST /auth/pair/redeem` from `AuthGate` and gets its own device cookie; the code is deleted on first use (a browser that is already logged in ignores it), and the fragment is replaced by `#<next>` before anything else loads so it does not survive in history. `npm start` prints such a link at startup — the first browser is logged in without ever seeing the token — and `sessionboxer open <id>` / `sessionboxer pair` produce them too.

**Devices are listable and revocable.** `GET /auth/devices` (with `current` marked for the caller), `DELETE /auth/devices/:id`, `POST /auth/logout` (revokes the caller's device and clears the cookie), `GET /auth/token` and `POST /auth/token/rotate` (writes a new token to `config.json`, deletes every *other* device). **Settings → Devices and remote access** (`Devices.tsx`) is the UI: the table, **Revoke** / **Log out**, **Pair another device** with QR, link, **Copy link** and a countdown, **Show access token** on demand, **Rotate token** behind a confirmation, and the address the Control Plane believes it is reached at.

**The browser gates itself.** `main.tsx` renders `<AuthGate>` around `<App>`: it asks `/auth/me` (and redeems a pairing fragment when there is one) before the app mounts, so no session list, settings or WebSocket is requested by a logged-out page; a login form otherwise. `api.ts` dispatches a `sessionboxer:unauthorized` window event on any 401 outside the login routes (fetch and the upload XHR), which flips the gate back to the login screen with a notice — that is how a revoked device or a rotated token is felt within one request. `subscribe()` (the `/api/ws` feed) backs off exponentially (1 s → 15 s) while its handshake keeps failing and asks `/auth/me` after each refusal to tell "Control Plane down" from "logged out". Terminal and Desktop sockets simply close; the feed's check sends the user to the login screen.

**The origin is configuration, not `location`.** `SESSIONBOXER_PUBLIC_URL` (validated to start with `http(s)://`, defaulting to the bind address) is the base of pairing links, the printed login link and the GitHub OAuth callback (`Settings` shows the resulting callback URL instead of `window.location.origin`). `SESSIONBOXER_TRUST_PROXY=1` is the explicit switch to believe `X-Forwarded-For` / `-Proto` / `-Host`; off by default because a tunnel connecting from `127.0.0.1` looks exactly like a local browser. `SESSIONBOXER_TLS_CERT` + `SESSIONBOXER_TLS_KEY` (both or neither) make the Control Plane serve HTTPS itself, for Headscale networks where no proxy can get a certificate for the node name. `PublicSettings.remote` carries `publicUrl`, `tls`, `accessTokenSource` and `trustProxy` to the UI.

**Keepalives.** The server pings every WebSocket client every 25 s (`WS_PING_MS`) and terminates the ones that did not pong by the next round — Cloudflare cuts idle WebSockets at 100 s, and dead phone connections are otherwise found only by a failed write.

**The CLI uses the token as a bearer.** `SESSIONBOXER_TOKEN`, then `SESSIONBOXER_ACCESS_TOKEN`, then the `accessToken` of the local `config.json` (so on the machine that runs the Control Plane nothing changes); `sessionboxer token` prints it, and a 401 / 403 from the server becomes a message that names the variable.

## Considered Options

- **Authentication only when not on loopback** (rejected): `tailscale serve`, `cloudflared` and any local reverse proxy connect from `127.0.0.1`, so "local" cannot be told from "remote" at the socket; always on, and the printed pairing link keeps the local first run at one click.
- **Token in the URL (`#token=`) or `localStorage`** (rejected): the token would sit in history, screenshots and every synced tab; a one-time pairing code in the fragment, consumed on first load and stripped from the URL, gives the same convenience without a durable secret in the browser. The cookie is HttpOnly so scripts cannot read it either.
- **Per-user accounts / OIDC** (deferred): one owner is the use case; Tailscale's ACL, Cloudflare Access or Headscale's user model already answer "who may connect", and the device list answers "which browsers". Nothing here prevents adding identities later.
- **A custom relay service** (rejected in the research): Headscale/Tailscale/Cloudflare Tunnel already do the rendezvous, NAT traversal and TLS; two or three sessions of our own relay would reproduce them badly.
- **Automatic certificates in the Control Plane (ACME)** (deferred): Let's Encrypt over HTTP-01 cannot see a tailnet-only name and DNS-01 needs a provider plugin per registrar; the cert/key files accept whatever `lego`, `certbot` or Caddy produced.
- **Client-side heartbeats** (rejected): the `ws` server ping is enough to keep proxies from cutting idle sockets, and browsers answer pings without any code.

## Consequences

- Every user sees a login screen once per browser after this update; `npm start` prints the pairing link to click. Scripts hitting `http://127.0.0.1:4000/api` need `Authorization: Bearer $(sessionboxer token)`.
- The token grants everything the UI can do; rotating it is the recovery for a leak. Cookies are as sensitive as the token for the device they belong to and are revocable one by one.
- Remote HTTPS is the user's to provide (Tailscale Serve, Caddy, Cloudflare, or the cert/key files) — the README's *Remote access* section walks through Headscale at `tunnel-sessionboxer.talayolabs.com`, Tailscale, Cloudflare Tunnel and a VPS; over plain HTTP from another host the clipboard, notifications and the VS Code pane are limited by the browser, not by Sessionboxer.
- The `Origin` check refuses legitimate cross-origin API use (another web app calling the Control Plane); the CLI and curl send no `Origin` and are unaffected.
- No Sandbox change: Daemons and images are untouched; the layout on a phone is still the desktop one (stage 2).
