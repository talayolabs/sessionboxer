# Auto-merge attached pull requests when GitHub allows it

Once the agent has opened a pull request and the reviews are in, the remaining work is waiting for CI and clicking **Merge**. The user wants that click done for them: a per-PR switch in the PR's tab, a check about every 10 seconds of whether the PR is allowed to merge, and the merge as soon as it is.

## Decision

**GitHub decides, Sessionboxer asks.** Eligibility is not recomputed from checks and reviews here; it is read from GitHub's own verdict, `mergeStateStatus` on the pull request (GraphQL, `MERGE_QUERY` in `github-pr.ts`), together with `state`, `isDraft`, `mergeable`, `reviewDecision`, `headRefOid` and the head commit's `statusCheckRollup` contexts (check runs and commit statuses, each with `isRequired(pullRequestNumber)`). `CLEAN` or `HAS_HOOKS` means merge; `UNSTABLE` (a check failing or still running that branch protection does not require) waits too, because the user asked for *all* checks to pass; `BLOCKED`, `DIRTY`, `DRAFT`, `UNKNOWN` wait and say why; `BEHIND` gets one `update-branch` per head so the base's commits are merged in and the checks rerun. The merge itself is the ordinary `PUT /repos/{owner}/{repo}/pulls/{n}/merge` with the chosen `merge_method` and the `sha` seen in the same check, so GitHub refuses (409) if the head moved in between and the next check starts from the new head; nothing bypasses branch protection, rulesets or required reviews, and a 405 refusal is recorded and not retried for that head and method.

**Persisted per PR, decided by the user.** `pull_requests` gains `auto_merge`, `merge_method` (`merge` | `squash` | `rebase`, default `merge`) and `merge_state` (JSON `PrMergeState`: `checkedAt`, `status`, `mergeable`, `headSha`, `checks[]`, `error`, `merged`). `PATCH /sessions/:id/prs/:prId` takes `autoMerge` and `mergeMethod`; enabling on a merged or closed PR is a 409. The switch is off by default and the UI asks for confirmation before turning it on; there is no session-wide or global default, because merging is the one PR action that cannot be undone.

**A second cadence in the same scheduler.** `PullRequests.tick()` (10 s) already drives the metadata polls at their minute-to-five-minute intervals; it now also runs `mergeCheck` for every PR in `listAutoMerge()` whose last check is older than `AUTO_MERGE_POLL_MS` (10 s), in the same promise chain as the polls so GitHub never sees concurrent requests from one Control Plane, with `retry-after`/rate-limit back-off honoured per PR. The check uses the same access path as watching (ADR-0027): `gh api` in the Sandbox as the login that attached the PR while the box is live, the matching GitHub Connector token while it is stopped, and a recorded error ("resume it to merge") when neither is available — auto-merge stays on and resumes when access returns. Turning the switch on runs a check right away; turning it off clears the state; a merge marks the PR `merged`, stores `merged: true`, and drops it from the list for good.

**Told, not discovered.** Every check updates `merge_state` and broadcasts the Session's `prs`, so the PR tab shows *waiting: 3 running — build, lint, e2e*, *waiting: conflicts with the base branch*, *waiting: reviews required*, *mergeable — merging now*, with the check list (state, required, link) and *checked 4s ago* underneath; the PR overview marks auto-merge rows. A merge sends a `pr_merged` WebSocket message (toast, browser notification) and a Web Push (ADR-0035) to sleeping devices, and the ordinary poll runs once more so the row reflects GitHub's final state.

## Consequences

- One GraphQL request per enabled PR every 10 seconds (≈ 360 points/hour per PR against a 5 000-point budget); nothing while the switch is off, and nothing once the PR is merged or closed.
- The safety of the merge is GitHub's: whatever the repository requires, Sessionboxer cannot merge around it, and a head pushed after the check is never merged blindly.
- A permanently failing non-required check keeps the PR waiting forever, shown as *n failed*; the user fixes the check or turns the switch off. This is the reading of "when all checks pass" the user asked for.
- Not done here: enabling auto-merge from a prompt or by the agent, GitHub's native "auto-merge" toggle (`enablePullRequestAutoMerge`, which needs the repository setting and would not report the checks here), branch deletion after merge, Bitbucket.
