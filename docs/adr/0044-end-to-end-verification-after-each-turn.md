# End-to-end verification after each turn: a Control Plane hook, a skill, run records in SQLite, a pane and a switch

The user wants the Agent to *prove* its work after every turn: look at what changed, derive a handful of test cases from what was asked, run them on the Sandbox desktop with the computer-use MCP (mouse, keyboard, screenshots, the browser in the box) while recording, fix and rerun what fails, and hand over the video. The cases, their progress and their timing must be visible in the UI while it runs, and the whole thing must be switchable.

## Decision

**The hook is the Control Plane, not a Provider hook.** `Sessions.afterTurn` already runs after every `turn_ended` (snapshot, then the saved-messages queue, ADR-0032). It now asks `E2eVerification.afterUserTurn` first: when the effective switch is on and the turn was a *user* turn that ended with `end_turn`, a run is opened in SQLite (`planning`) and a **hidden follow-up prompt** is sent with `origin: "e2e"` — the mechanism of the hidden `/context` prompt (ADR-0030), so it works for Claude Code and Devin alike and needs nothing Provider-specific. The saved-messages queue is held while the verification turn runs and pumped when it ends, so a queued message never lands in the middle of a run. Queued saved messages are user turns too and are verified like typed ones.

**Loop guard.** A turn whose `user_prompt` carries `origin: "e2e"` is a verification turn: it is never verified itself, its end closes whatever the Agent left open, and a second run is never started while one is `planning`/`running`/`fixing`. The web hides the hidden prompt from the transcript (a small *verifying…* marker instead) and shows the run's marker at the turn's end.

**Answer-only turns are recorded, not ignored.** A user turn with no `tool_call` at all (an explanation, a question answered from memory) is persisted as a `skipped` run with the reason "The turn used no tools, so nothing in the workspace changed" without waking the Agent; a turn that did use tools is left to the skill's own *Decide* step, which may still `e2e_plan` a skip with a reason (research, reading, a `git log` — nothing testable changed).

**The skill.** `images/sandbox/skills/e2e-verification/SKILL.md` is installed at `/home/agent/.claude/skills/e2e-verification/` in the image (the Claude Code skills location; the hidden prompt names the file so Devin reads it too). Its steps: *Decide* (`git status --short` / `git diff --stat` in every repository under `/workspace`, plus the turn itself), *Plan* (2–5 cases, up to 10 only for a very large change; title, steps, expected result), *Run* (one desktop recording for the whole run, `annotate_recording` `test_start`/`assertion` captions, one `e2e_case_start` … `e2e_case_end` per case with a note and a screenshot path), *Fix and rerun* (a failed case is fixed as normal work and rerun as a **new cycle** of the same case, at most `E2E_MAX_FIX_ATTEMPTS = 3` fix attempts per case, enforced by the Control Plane), *Finish* (`stop_recording`, `e2e_finish` with the video path and a summary, and a reply that names `/workspace/recordings/….mp4` so the existing inline-media rendering (ADR-0017) shows the video in the chat). Claude Code `Stop` hooks were evaluated and not used: a hook runs inside the Sandbox, cannot read the switch, and would have to open the run before the Control Plane knows about it; the hidden prompt keeps the Control Plane the single source of truth and works for every Provider.

**Run records live in SQLite.** `e2e_runs` (`status: planning | running | fixing | passed | failed | skipped | aborted`, `skip_reason`, `started_at`/`finished_at`, `video_path`, `cycles`, `summary`) and `e2e_cases` (one row per *attempt*: `idx`, `cycle`, `title`, `steps`, `expected`, `status: pending | running | passed | failed | skipped`, timing, `note`, `screenshot_path`), created by the schema on first start like every other table. `GET /api/sessions/:id/e2e` lists the runs with their cases, `…/e2e/:runId` one run, and each change is broadcast as `e2e_changed` with the whole run, like `pr_changed`. An `e2e_run` transcript event is appended when a run closes, so the marker survives reloads, forks and branches like every other divider. Runs left open by a Control Plane restart are closed as `aborted` on start; stopping or deleting the Session aborts its open run.

**The Sandbox writes through the Daemon.** The Sandbox has no route to the Control Plane API (ADR-0005), and the Control Plane is the WebSocket *client* of the Daemon. Four tools in the computer-use MCP (`e2e_plan`, `e2e_case_start`, `e2e_case_end`, `e2e_finish`) POST to the Daemon's loopback HTTP `/e2e`; the Daemon turns each into a JSON-RPC *request* on the Control Plane's WebSocket (`_sessionboxer/e2e/plan` …), the first reverse request in the protocol; `DaemonClient` answers it (`onRequest`) and the Daemon relays the answer — the updated run or an error — to the tool, with a 20 s timeout and a 503 while no Control Plane is connected. The tool results carry the Control Plane's error text verbatim ("no run is open", "already run 4 times, leave it failed"), which is what steers the Agent.

**UI.** A `Verification` pane (`Pane = "e2e"`): switch and effective state in the toolbar, the current or last run with a status badge, headline ("3/4 passed · 1:42 · cycle 2"), progress bar, the case list with status, live timer for the running case, cycle badge, note, screenshot thumbnail and the steps/expected on click, the video as an attachment card when done, and earlier runs in a collapsible section. When a case flips to `running` for the Session the user is looking at, the pane opens through `setPaneRequest` — the PR pane's mechanism — and never for another Session. The pane tab shows a pulsing dot while a run is open. On the phone it is a bottom tab like the others. The transcript marker at the turn's end ("Verified: 4/4 passed · 2:13 · video", or "Verification skipped: …") opens the pane on that run.

**Switch.** `Settings.e2eVerify` (default **off**) and `SessionSettings.e2eVerify: boolean | null` (`null` = follow Settings; ADR-0039: one object, one form, editable live, kept by forks), plus the pane's quick toggle and `sessionboxer new --e2e | --no-e2e`. Off by default because a verification turn costs a second turn of model time and a few minutes of desktop work after every prompt; a user who wants it flips one switch.

## Considered Options

- **A Claude Code `Stop` hook** (rejected as the trigger, see above; the skill file it would call is installed anyway so the user can ask for `/e2e-verification` by hand).
- **A loose file (`/workspace/.e2e/cases.json`) written by the Agent** (rejected): the UI would have to poll the Sandbox, the records would leave with the Workspace, and nothing would enforce the cycle cap.
- **A separate MCP server for the lifecycle tools** (rejected): the computer-use MCP already runs in every Sandbox and the tools belong next to `start_recording`; four tools do not justify a second process.
- **A Daemon *notification* instead of a request** (rejected): the Agent needs the answer (the run, the "no run is open" refusal, the cap) to steer itself.
- **Verify queued saved messages differently from typed ones** (rejected): both are user turns; the queue simply waits for the verification.
- **Default on for fresh installs** (deferred): the switch is one click and the cost is real; revisit when the skill has proven itself.

## Consequences

- Every completed turn of an opted-in Session is followed by a hidden turn: the Session shows `running` a second time, the Agent's context grows by the skill and the run, and the recording takes real minutes. Skipped runs cost nothing.
- Fix attempts happen *inside* the verification turn, so a fix is also snapshotted (the verification turn's own `afterTurn` snapshot) and lands in the same branch; the transcript shows the fixes as normal Agent work under the *verifying…* marker.
- The Daemon protocol gains its first Control-Plane-answered request; a Daemon talking to an older Control Plane gets a JSON-RPC "method not found" error, which the tool reports to the Agent.
- The Sandbox image must be rebuilt (skill, MCP tools, briefing).
- Not done here: verifying Devin's use of the skill file in the field (Devin reads the path from the hidden prompt), a per-case retry from the UI, and a "verify now" button for a turn that was skipped.
