# Codex as a third Provider, on a ChatGPT login

OpenAI's Codex CLI is the third widely used coding agent after Claude Code and Devin, and it speaks ACP through `@agentclientprotocol/codex-acp` (the adapter maintained in the ACP organisation, bundling `@openai/codex`). Everything Sessionboxer does with an Agent is generic ACP already (ADR-0006, ADR-0007): `session/new`, `session/load` for Resume, `session/fork` for branches, config options for the model and the rest, client MCP servers, `usage_update`. What is specific to Codex is how it is paid for: the user wants the ChatGPT subscription, not an API key billed per token, and that credential is not a token to paste but a file Codex keeps rewriting.

## Decision

**Provider `codex`, label "Codex"**, alongside `claude-code` and `devin`; OpenAI is the company and ChatGPT the subscription, the agent is Codex. The image installs `@agentclientprotocol/codex-acp` pinned (`CODEX_ACP_VERSION`) and exposes the bundled `codex` CLI; the Daemon starts `codex-acp` with `INITIAL_AGENT_MODE=agent-full-access` and the image ships a `~/.codex/config.toml` with `approval_policy = "never"` and `sandbox_mode = "danger-full-access"`: the Sandbox is the isolation, as for the other Providers, so Codex runs without approvals and without its own sandbox. `agent-full-access` joins the list of modes the Daemon treats as "approve everything". `~/.codex/AGENTS.md` carries the Sandbox briefing (Codex reads global instructions from `$CODEX_HOME/AGENTS.md`) and `~/.agents/skills` points at the shared skills directory, where Codex looks for user skills.

**The credential is `~/.codex/auth.json`, pasted once.** The user runs `codex login` on their own machine (browser, ChatGPT account) and pastes or imports the file in Settings, like `claude setup-token` and Devin's credentials file. The Control Plane validates it (a JSON object holding ChatGPT tokens or an API key; anything else is a 400 that says what to do), stores it compacted under `providerSecrets.codex.CODEX_AUTH_JSON`, and shows only what the id token claims — email, plan, last refresh, whether it is an API key — never the file. There is no `OPENAI_API_KEY` field: a key in `auth.json` works, but the product path is the subscription.

**The file travels over the Daemon RPC and lives on tmpfs.** Unlike the other Providers' tokens it is not an environment variable: Codex rotates the OAuth tokens in place and rewrites the file, which a fixed environment value could not follow, and `docker inspect` would show it. On every connection the Control Plane sends `_sessionboxer/codex/auth/set` (before the MCP set that starts the Agent); the Daemon writes `/dev/shm/sessionboxer/codex-auth.json` (mode 0600) and points `$CODEX_HOME/auth.json` at it with a symlink, so the rest of `~/.codex` (config, session rollouts that `session/load` needs) stays on the container disk and Stop/Resume keeps the conversation, while `docker commit` (Snapshots) never carries a token — only a dangling symlink. Sessions of that Provider are refused until a login is configured, and forgetting the login in Settings removes the file from every running Codex box.

**Refreshed tokens flow back.** The Daemon watches both directories; when Codex rewrites the file (in place, or by replacing the symlink with a regular file, which the Daemon moves back onto tmpfs within half a second) it reports the new contents with `_sessionboxer/codex/auth/changed`. The Control Plane accepts a report only from the authenticated connection of that Session, keeps it only when `last_refresh` is not older than what it holds, stores it, and pushes it to the other running Codex Sessions, so several boxes share one login without one of them invalidating the others' refresh token. An older file, or a malformed one, is ignored and logged without its contents.

**What stays Provider-specific elsewhere is unchanged.** LLM inspection (ADR-0032) remains Claude-only; Devin's MCP config file remains Devin's; compaction details (ADR-0031) say plainly that Codex's records cannot be read yet rather than guessing at another Provider's format.

## Considered Options

- **`OPENAI_API_KEY` in Settings, like the Devin token**: half a session and trivially secure, but paid per token at API prices; the user wants the subscription. Left out of the UI on purpose; a key inside `auth.json` still works.
- **"Log in with ChatGPT" from Sessionboxer (device code, like the GitHub CLI login of ADR-0019)**: the device flow is disabled for many ChatGPT workspaces (openai/codex#9253) and would still leave the refresh problem; pasting the file is the same effort as the other two Providers' tokens. Can be added on top later.
- **Auth as an environment variable or a `docker commit`-safe volume**: an environment value cannot follow the refresh and is visible in `docker inspect`; a named volume would outlive the Session and be shared between boxes with no arbitration.
- **Whole `CODEX_HOME` on tmpfs**: simplest for secrecy, but Codex keeps its session rollouts there and `session/load` on Resume would find nothing.
- **Refresh sync by polling the boxes**: the Daemon already watches the file for its own symlink repair; pushing the change is cheaper and immediate.

## Consequences

- Needs an image rebuild; existing Sandboxes keep working as before (a Daemon that predates this answers "method not found" to the auth push and is logged as such).
- The login is only as private as `~/.sessionboxer/config.json`, same as the other tokens; it is never in public settings, events, `docker inspect`, Snapshots or logs (checked with a marker token).
- Verified with a fake login: delivery over RPC before the Agent starts, `auth.json` → tmpfs with mode 0600, `codex-acp` starting with `CODEX_HOME` and `INITIAL_AGENT_MODE` and reporting models and options, in-place and rename-style refreshes stored on the host and reflected in Settings, an older file ignored, forgetting the login removing the file, no marker in `docker inspect`, events, the committed image or the Control Plane log. A prompt with invalid tokens ends the turn with Codex's own "Your access token could not be refreshed. Please log out and sign in again." A turn with a real ChatGPT login is still to be run.
