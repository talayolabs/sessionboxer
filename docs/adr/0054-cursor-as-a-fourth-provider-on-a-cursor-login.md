# Cursor as a fourth Provider, on a Cursor login

Cursor's CLI (`agent`, installed as `cursor-agent`) speaks ACP natively: `agent acp` is stdio JSON-RPC with `session/new`, `session/load`, `session/list`, permission requests, config options (the model under id `model`), modes (`agent`, `plan`, `ask`) and client MCP servers over stdio, HTTP and SSE. So, as with Codex (ADR-0046), everything Sessionboxer does with an Agent applies unchanged; what is specific is how it is paid for — the user's Cursor subscription — and that Cursor's credential, like Codex's, is a file its CLI rewrites.

## Decision

**Provider `cursor`, label "Cursor"**, alongside `claude-code`, `devin` and `codex`. The image unpacks the package Cursor's own installer downloads (`CURSOR_CLI_VERSION`, the same URL as `curl cursor.com/install`), with the Node it bundles, into a root-owned `/opt/cursor-agent`, and links `cursor-agent` and `agent` into the PATH; the two `*-sea` binaries in the package are left out (they are the code-signed re-exec the CLI uses on macOS only, 270 MB). The Daemon starts `cursor-agent --disable-auto-update --force --approve-mcps --trust acp`: no update at start, no approvals for commands or MCP servers, the workspace trusted — the Sandbox is the isolation, as for the other Providers — and `agent` joins the modes the Daemon treats as "approve everything". A `~/.cursor/cli-config.json` in the image turns Cursor's own sandbox and notifications off, and keeps its name out of commits and PRs (the rule of ADR-0022's default instructions). The Sandbox briefing sits at `/AGENTS.md`: Cursor reads `AGENTS.md` from the workspace and every directory above it, so this one is found from `/workspace` and from every repository under it, without being inside any of them.

**The credential is Cursor's `auth.json`, or an API key, pasted once.** The user runs `agent login` on their own machine and pastes or imports the file it writes (`~/.config/cursor/auth.json` on Linux, `~/.cursor/auth.json` on macOS, `%APPDATA%\Cursor\auth.json` on Windows), or pastes a key from the Cursor dashboard; both use the subscription. The Control Plane accepts a JSON object with an `accessToken` or an `apiKey` (compacted; anything else is a 400 that says what to do) or a single token without whitespace, under `providerSecrets.cursor.CURSOR_LOGIN`; `CURSOR_API_KEY` in the Control Plane's environment overrides it. Settings shows only what the login is — an API key, or a login and until when its access token is valid (the JWT's `exp`) — never the file.

**The login travels over the Daemon RPC.** On every connection the Control Plane sends `_sessionboxer/cursor/auth/set` before the MCP set that starts the Agent. A file goes on tmpfs the way Codex's does — `/dev/shm/sessionboxer/cursor-auth.json`, mode 0600, `~/.config/cursor/auth.json` a symlink to it, so `docker commit` carries a dangling link and the rest of `~/.cursor` (config, session records for `session/load`) stays on disk — through the same `AuthFile` helper, which also watches both directories, moves a file Cursor writes over the symlink back onto tmpfs, and reports a rewritten file with `_sessionboxer/cursor/auth/changed`. An API key is handed to the Agent process as `CURSOR_API_KEY` instead, never as a container environment variable (not in `docker inspect`); switching between the two restarts the Agent, after the turn if one is running, and the response says whether it was applied at once. The Control Plane keeps a reported file only from that Session's connection, when it is a login (never over an API key) whose token is not older than the one it holds, and pushes it to the other running Cursor Sessions.

**The Daemon never calls ACP `authenticate`.** Cursor's ACP marks itself authenticated at start from the file or the key; `authenticate` with its one method, `cursor_login`, starts a browser login flow, which cannot complete in a box. Sessions of the Provider are refused until a login is configured, and forgetting it in Settings removes the file from every running Cursor box.

**Cursor's ACP extensions are answered so a turn never hangs.** Beyond the standard protocol Cursor sends `cursor/ask_question` (multiple-choice questions to the user, blocking), `cursor/create_plan` (hand over a plan for approval, blocking), and the notifications `cursor/update_todos`, `cursor/task` (subagent runs) and `cursor/generate_image`. The Daemon answers a question with *skipped* and the reason that the model should ask in the chat, accepts a plan, and logs the rest; all are parsed against typed schemas taken from the CLI package.

**Usage.** Cursor reports no usage windows over ACP and its model calls do not pass through the box, so the usage bars are hatched with a pointer to the Cursor dashboard, like Devin's.

## Considered Options

- **`CURSOR_API_KEY` only, like the Devin token**: simple and secure, but requires creating a key in the dashboard; the login file is what `agent login` produces and what most users have. Both are accepted in one field.
- **Running `agent login` from the box**: the browser flow needs cursor.com to call back to the CLI's local port, which would have to be reached through the Desktop pane; pasting the file is the same effort as for Codex.
- **The whole Cursor package as the installer lays it out (558 MB)**: the macOS-only signed binaries are half of it; leaving them out changes nothing on Linux (the re-exec is gated on `darwin`).
- **A separate `CURSOR_AUTH_TOKEN` field**: the CLI accepts one, but it is what `auth.json` holds; the file covers it and refreshes.

## Consequences

- Needs an image rebuild (about 300 MB); existing Sandboxes keep working as before (a Daemon that predates this answers "method not found" to the auth push and is logged as such).
- The login is only as private as `~/.sessionboxer/config.json`, same as the other tokens; it is never in public settings, events, `docker inspect`, Snapshots or logs.
- Verified without a Cursor account: `cursor-agent acp` in the image initialises (protocol 1, `loadSession`, MCP over HTTP/SSE, images in prompts, `cursor_login` as the auth method) and refuses `session/new` with *Authentication required* until a login is present; the login reaches the box over RPC before the Agent starts, as a file on tmpfs or as `CURSOR_API_KEY` in the Agent process only; settings validation and the refresh rule. **A turn with a real Cursor login has not been run**: the first session on a real login is the test of the model list, the modes, the MCP hand-over and the extension calls.
