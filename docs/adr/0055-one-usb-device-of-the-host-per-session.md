# One USB device of the host per Session

A phone, a board or a dongle plugged into the machine that runs Sessionboxer should be usable by the Agent in one Sandbox — `adb devices` sees the phone, `adb install` works — without the Sandbox seeing the machine's other USB devices, and without breaking every time the device re-enumerates. On Linux a USB device is a character node `/dev/bus/usb/BBB/DDD` (major 189, minor `(BBB-1)*128 + DDD-1`) whose number changes on every reconnect, reset, USB-mode change and Android "Allow USB debugging" toggle; Docker's `--device` pins one path at container creation and cannot follow it, and bind-mounting all of `/dev/bus/usb` hands over every device. Under Sysbox (ADR-0008) `mknod` inside the container is refused outright. Docker Desktop, OrbStack and Colima have no USB passthrough; WSL2 gets a device only through usbipd-win, which attaches it to the whole VM.

## Decision

**A per-Session Docker volume at `/dev/bus/usb`, with only the connected device's node in it.** Every Sandbox is created with the named volume `sbx-usb-<sessionId>` mounted at `/dev/bus/usb`, the device-cgroup rule `c 189:* rmw` (the kernel's permission to open USB nodes; a rule alone shows nothing) and, in the plain runtime, `CapDrop: MKNOD` so the box cannot forge a node for another device (Sysbox refuses `mknod` on its own; the privileged mode is what it says). The volume is empty until the user connects a device. A node is made by a short-lived helper container (the Sandbox image, `/bin/sh`, network `none`, `CapDrop ALL` plus `MKNOD`/`CHOWN`/`FOWNER`/`DAC_OVERRIDE`) that mounts the volume, wipes it and creates `BBB/DDD` as `crw------- 1000:1000` — the Agent's user and nobody else in the box. Deleting the Session deletes the volume.

**One Session per device, enforced by the Control Plane.** `usb.ts` lists the host kernel's devices from `/sys/bus/usb/devices` (root hubs, hubs and interfaces left out; identity `vendor:product:serial`, or `vendor:product@<sysfs name>` without a serial), keeps each claim in `Session.usb` (`SessionUsb`: identity, name, current node, WSL bus id), and serialises connect/disconnect/reconcile on one queue. Connecting a device that another Session holds first clears that Session's node and claim (event `usb_changed: disconnected`, a prompt note saying why), then creates the node in the new Session's volume; the response is the Session with its `usb`. Sessions created before this ADR have no volume and no cgroup rule, and are refused with a 409 that says to recreate them.

**Re-enumeration is followed, not fought.** Every 2 s the Control Plane matches each claim against sysfs by identity; when the node path changed it rewrites the volume (helper run), updates `Session.usb.node` and tells the Agent the new path (or that the device is unplugged, node `null`, the sidebar icon turning amber). Stop/Resume keeps the volume and the claim; the node is still right when the box comes back, or is refreshed by the next reconcile.

**WSL2 is a first-class host.** When the Control Plane runs in WSL2 (`WSL_DISTRO_NAME` or `/proc/version`) it also asks Windows: `usbipd.exe state` (JSON; WSL interop runs Windows executables from Linux, with the cwd on `/mnt/c` so Windows does not complain about a UNC working directory) lists every Windows USB device with its bus id, whether it is shared (`PersistedGuid`) and attached (`ClientIPAddress`), and is matched to the kernel list by `vendor:product` and serial. Connecting an unattached device runs `usbipd.exe attach --wsl --busid <id> --auto-attach` as a supervised child, waits up to 25 s for the device to appear in sysfs, and keeps the child alive so usbipd re-attaches after the device's own resets (an Android authorisation toggle drops the USB/IP attachment); the reconcile loop restarts the child when it dies while the device is missing. An unshared device needs `usbipd bind`, which needs administrator rights: the Control Plane asks for a UAC prompt (`powershell.exe Start-Process usbipd -Verb RunAs -Wait`) and, if that is refused or fails, answers 409 with the command to run once by hand. Disconnect (and the Session's deletion) runs `usbipd.exe detach`, giving the device back to Windows. Without usbipd-win the Windows list is empty and the host note says how to install it; devices attached by other means still show up from sysfs.

**The UI**: the session's ▾ menu has **Connect USB device…** (or `USB: <name>` when one is connected, lit) opening a dialog with the host's devices, who holds each, Connect / Take over / Disconnect, and the host note (WSL hints); the sidebar shows a USB glyph next to Sessions holding a device (amber when it is unplugged right now); the transcript marks connections and disconnections. The Agent is told in a prompt note what the device is, where it is, that it is the only USB device it can reach, that nothing talking to it is preinstalled, and that its number changes on re-enumeration.

**The image stays as it is.** No `adb`, `platform-tools`, `scrcpy` or udev rules are added: what talks to the device is the Agent's to install (`apt-get install adb`), as any other tool. The adb key then lives in the box (`~/.android/adbkey`), so the phone's authorisation prompt is answered once per Sandbox and survives Stop/Resume and Snapshots.

## Considered Options

- **Sharing the host's adb server** (`ADB_SERVER_SOCKET=tcp:host:5037`, a serial-scoping proxy per Session): the most portable answer (works with Docker Desktop VMs), but it needs adb on the host and in the image, and it is Android-only. Kept as a possible later addition on top of this one; this ADR is about the raw device, for any USB device.
- **`--device /dev/bus/usb/BBB/DDD` on the container**: pinned at creation; the first re-enumeration leaves a dead node and no live one, and connecting a device later would mean recreating the container.
- **Bind-mounting `/dev/bus/usb` with the cgroup rule**: follows re-enumeration for free (the host's udev updates the directory), but every device of the machine is in every such box.
- **`mknod` inside the Sandbox over `docker exec`**: works under runc, refused under Sysbox (`Operation not permitted` even as root); and it needs `CAP_MKNOD` in the box, which is what lets the Agent reach other devices. The helper container keeps the capability out of the box for both runtimes.
- **Injecting a bind mount into the running container's mount namespace** (`nsenter --mount`): fails under both runtimes from a helper container; and it cannot be done through the Docker API alone (compose mode).
- **A global "USB devices" settings page**: the device is a property of the Session that holds it, so the picker lives in the Session's menu, where the take-over is explicit.
- **Handing the same device to several Sessions**: two adb servers on one phone fight over its USB interface; one Session per device is what the user asked for and what USB itself tolerates.

## Consequences

- Sandboxes created from now on have an empty `/dev/bus/usb` and the cgroup rule; nothing changes for them until a device is connected. Older Sandboxes cannot take a device until recreated (the dialog says so).
- The node is a plain character device owned by `agent`; a process in the box that can become root (sudo is passwordless there) can also open it, but cannot make nodes for other devices (`CAP_MKNOD` dropped; Sysbox refuses `mknod`). Privileged Sandboxes (ADR-0008 without Sysbox) could always reach every device; unchanged.
- Verified on Linux with a USB/IP virtual gadget: connect, read from the node as `agent` (and `Operation not permitted` for `mknod`, also under `sudo`), take-over between two Sessions, unplug → `null` → new number on re-plug, Stop/Resume, disconnect, delete removing the volume — under runc and under Sysbox. **The WSL2 path (usbipd state parsing, `attach --wsl --auto-attach`, the UAC prompt for `bind`, `detach`) follows usbipd-win's documentation and has not been run on a Windows machine**; the first Windows user with a phone is its test.
- Docker Desktop / OrbStack / Colima users get a host note saying USB is not available there.
