# ADR 0073: Utilities — the systems around the software, registered once, used by name

## Status

Accepted

## Context

An agent that investigates an incident, checks that a deployment works or reproduces a bug needs what an engineer has: New Relic, Grafana, Graylog, Argo CD, the RabbitMQ admin UI, MongoDB, the QA deployment, a bastion host — each with a login, sometimes a 2FA code, sometimes only reachable through a jump host. Until now each of those was either an MCP server the user registered by hand (with the token in its environment) or nothing at all: the agent did not know the systems existed, and the only way to let it log into a web UI was to paste the password into the chat, where it stays in the transcript, the model's context and every snapshot of the conversation.

Two names were in the way. "Tool" is what an MCP server exposes and what the model calls; "Environment" was the Docker / Windows / macOS choice of a Session, while the systems above live in *prod*, *staging* and *qa*. The design and research are in `docs/research/runtime-debugging-utilities.md`.

## Decision

**A `Utility`** (Settings → Utilities) is one such system in one target **Environment**: a name (`newrelic`, `grafana-payments`), a **group** — *Observability* (where to look) or *Applications* (what to poke) —, **credentials** by name (`user`, `password`, `token`, `totp`, `ssh_key`, anything), a read-only flag (default on), notes for the agent, and up to five **facets**: `web` (URL, login kind), `http` (base URL, headers that may say `${cred:token}`), `ssh` (host, port, user, jump), `cli` (install step, environment variables) and `mcp` (an MCP server definition without a name of its own). Presets (New Relic, Grafana, Graylog, Argo CD, RabbitMQ, MongoDB, a web app, an SSH host) fill the facets from one URL. **Environments** are a list in Settings (`prod` production, `staging`, `qa` by default); a production Environment is off for new Sessions and the agent is told to look, not change. **The Docker / Windows / macOS axis is now called the Machine** in the UI; the protocol keeps `environment` internally.

**Secrets are write-only and travel one way.** The public schema replaces stored secret values with `null`, as MCP servers do (ADR-0032); the browser never sees them again. A Session gets only the Utilities it has on, resolved by the Control Plane (`${cred:…}` filled in, `localhost` rewritten) and pushed to the Daemon (`_sessionboxer/utilities/set`), which writes them as `0600` files on the Sandbox's tmpfs (`/dev/shm/sessionboxer/utilities/<name>.json`) — never in the Workspace, never in a snapshot — and a secret-free manifest `.sessionboxer/utilities.json` (names, facets, credential *names*) for the agent to read. The agent reaches a credential by name only: `${util:<name>.<credential>}` and `${util:<name>.otp}` inside the desktop `type` tool are replaced by the computer-use MCP on the way to the screen (the tool result says "filled in", not the value); `sb-util env|curl|ssh|tunnel|otp|open` in a shell reads the tmpfs files itself. A Utility's `mcp` facet becomes an ordinary MCP server of the Session (ADR-0032 path, name = the Utility's) with its secrets resolved by the Control Plane like any other server's — one code path for restart and deferral. Windows and macOS guests get the manifest and the procedures; the tmpfs files stay in the Linux Sandbox (the guest's agent uses the MCP facets and the web UIs through the Desktop; `sb-util` is Linux-only for now).

**One entry point for the agent** is the `sessionboxer` MCP: `utilities_list` / `utilities_get` (the catalogue, credential names only), `utilities_enable` (a card to switch on; immediate off), `utilities_open` (the web UI in the Desktop), `utilities_add` / `utilities_update` (register from a description — "add newrelic with user X password Y at URL Z" — through an approval card that shows every field with secrets masked; the call's input is stored in the transcript with the credential values masked) and `procedure_save`. The chat has a `/util …` composer command that opens the same form in the browser and stores the Utility without the message ever reaching the agent, for when the user has the credentials at hand. The Session's switches (New Session, Fork, Session settings → Utilities) work at three levels — group, Environment, Utility — and the header's settings chip counts them with the MCP servers.

**Procedures are skills.** A `ProcedureDef` (name, description, Markdown body, the Utilities and Environments it applies to, source user/agent) is stored in Settings and materialised by the Daemon as `~/.claude/skills/<name>/SKILL.md` (the directory the agents already read, ADR-0068) in every Session whose enabled Utilities and their Environments match; a Session with no Utilities on gets none. The Settings page edits, imports (`SKILL.md` files) and exports them and ships an "Investigate an incident" template; the agent proposes one with `procedure_save` after an investigation worked.

## Consequences

- Sessions know what systems they may look at and how, without the user pasting anything into the chat; the transcript, the model's context, snapshots and the Workspace never contain a credential. What the model *does* see is what it typed around the placeholders and what the screen shows afterwards.
- A Utility's MCP server appears in the agent's tool list only while the Utility is on, so turning *prod* off really removes it. The ordinary MCP registry is unchanged; the Utilities page owns Utility-managed servers.
- The tmpfs files are readable by anything running as the Sandbox user — the agent's own commands included. `sb-util` and the placeholders are conveniences that keep values out of the transcript; they are not a barrier against an agent that `cat`s the file, which the briefing forbids. Least-privilege credentials and read-only accounts remain the user's job.
- `sb-util curl` guesses the auth (basic from `user`/`password`, bearer from `token`) only when the facet's headers do not carry one; SSO web logins are the agent's to work through in the Desktop.
- Image rebuild: `sb-util`, the computer-use MCP and the briefing changed.
