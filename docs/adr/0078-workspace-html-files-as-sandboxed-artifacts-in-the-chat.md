# Workspace HTML files as sandboxed Artifacts in the chat and an App pane

An Agent that writes `/workspace/game.html` (a canvas, inline JS, a chart library from a CDN) and names it in its reply got, until now, a text preview of the markup: `MEDIA_TYPES` had no `html` entry, so `/fs/raw` served it as `application/octet-stream` and the chat showed the source. The research in `docs/research/canvas-and-html-apps-in-the-chat.md` sorts the ways an Agent could show a running UI into three: single HTML files from the Workspace (this ADR), live servers in the Sandbox (not yet) and MCP Apps (a separate stream). This ADR is the first: a self-contained HTML file runs as an interactive "Artifact" inline in the chat and in a new App pane.

## Decision

**Agent HTML never runs on the Sessionboxer origin.** It is never put into the React tree, never into `Markdown.tsx` (whose sanitiser is untouched), never served with the page's cookies usable. A new Daemon route `GET /fs/app?path=…`, proxied as `GET /api/sessions/:id/fs/app?path=…`, serves `.html`/`.htm` files exactly as `/fs/raw` finds them (same `WorkspaceFs` containment, same guest transport on Windows/macOS) but with `Content-Type: text/html; charset=utf-8`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and a Content-Security-Policy whose first directive is **`sandbox allow-scripts allow-pointer-lock`**. A CSP `sandbox` is applied by the browser to the document itself, so the page has an opaque origin (`window.origin === "null"`) in the chat's iframe, in the App pane and when its URL is opened in a tab of its own: no cookies, no `localStorage` shared with Sessionboxer, no same-origin access to `/api`. The iframe's own `sandbox="allow-scripts allow-pointer-lock"` attribute is the second fence, not the first. The rest of the policy is the Artifacts policy: `default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' <cdns>; style-src 'unsafe-inline' <cdns>; img-src data: blob: <cdns>; font-src data: <cdns>; media-src data: blob:; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`. The Daemon sets this policy with the shipped CDN list; the Control Plane replaces it with one built from **`Settings.htmlAppCdns`** (Global settings → Agent → "HTML app CDN allowlist"; default cdnjs, jsDelivr, unpkg, esm.sh, fonts.googleapis.com, fonts.gstatic.com).

**`/fs/raw` keeps `.html` inert.** The media kind `html` exists so the chat recognises the path and `contentTypeFor` answers `text/html`, but on `/fs/raw` an HTML file always goes out with `Content-Disposition: attachment` and `nosniff`: a download, never a document. No other kind changes.

**`Origin: null` is refused on the API** except for `GET`/`HEAD` of `/sessions/:id/fs/raw` and `/sessions/:id/fs/app`. A sandboxed document sends `Origin: null` on its fetches; `rejectCrossOrigin` used to let that through, counting on `SameSite=Lax` to keep the cookie away, and now answers 403 before authentication (`Auth.allowsNullOrigin`). The two file routes stay open to it because an Artifact that embeds `<video src="/api/sessions/…/fs/raw?…">` or `<img>` of a Workspace file sends `Origin: null` on Range requests; `connect-src 'none'` already stops `fetch`. The frame's own navigation sends no `Origin` header, logins and pairing happen from the Sessionboxer page (a real origin) and WebSocket upgrades carry the page's origin too, so none of those is touched.

**Caps.** The Daemon refuses an app over **16 MiB** with 413 (`/fs/raw` has no cap and streams Ranges; an app is read whole by the browser). The inline card runs a file up to **2 MiB** as soon as the HEAD succeeds and shows **Run** above that; the size comes from the HEAD of the `fs/app` route, which is also what tells "not found", "Sandbox stopped" and "too large" apart.

**Single file, v1.** The CSP has no `self` anywhere, so an HTML file that refers to `./app.js` or `./style.css` finds them blocked (and the Control Plane would answer their path with 401 anyway, there is no directory route). Agents are told so in the Sandbox briefing ("Handing files to the user"): inline CSS and JS, imports only from the allowlist, no fetch/XHR, no relative files, under 2 MB to start on sight. A directory app (an `index.html` with siblings) needs a tokenised route per directory that scopes relative URLs and gives each app its own origin; that is v2, together with live-server previews.

**The card and the pane.** `AttachmentCard` renders an `html` attachment as an `<iframe sandbox referrerpolicy="no-referrer" src=<fs/app>>` in a fixed-height, user-resizable frame with a toolbar: Run/Stop (unloads the frame), Reload (a new `v=` nonce), Open in App pane, Fullscreen (`requestFullscreen` on the wrapper) and Source (the Code pane, through the existing `OpenFile` context). The **App** pane (`"app"` in `Pane`, a tab after Code, `ui_open` accepts `app`) shows the last Artifact opened from this Session's chat, remembered per Session in the browser, with its path (a click opens the source in Code), Reload, Fullscreen, Source and Open in new tab. It reloads when the file changes without polling: the pane asks `POST /api/sessions/:id/fs/watch {path}`, the Daemon watches the file's directory with `fs.watch` (so an editor's write-and-rename is seen too; at most 32 files, least recently asked dropped first, 150 ms settle) and sends `_sessionboxer/fs/changed`, which the Control Plane broadcasts as `fs_changed` to the UI sockets. A VM Session's mirror only moves when a file is served, so on Windows and macOS the pane reloads by hand.

**The prompt preview** (a file picked for a prompt, before it is sent) stops treating `.html` as text: the dialog shows it in an iframe with an empty `sandbox` (no scripts), a static render of the user's own file.

## Considered Options

- **Rendering the HTML in the React tree after sanitising it**: no sanitiser keeps scripts, and an Artifact without scripts is a document, not an app. Rejected.
- **The `sandbox` attribute alone**: the URL can be opened in a tab, bookmarked or linked; only a CSP `sandbox` follows the document there.
- **A `srcdoc` iframe fed by a fetch**: avoids a route, but the document inherits the page's origin unless sandboxed, cannot carry a CSP header, and loses the "open in a tab" case. The route is simpler and the CSP is enforced server-side.
- **Serving apps from a second hostname** (`*.apps.localhost`): the right end state for directory apps and live servers, but needs DNS, certificates and the tunnel's cooperation; CSP `sandbox` gets the same isolation for one file today.
- **Keeping `Origin: null` allowed and trusting `SameSite=Lax`**: the sandboxed document is on the same site as the API in the browser's eyes for `Lax` purposes only in navigations; the check is cheap and explicit, and the two file routes are the only ones a sandboxed page has a reason to call.
- **Polling the file's mtime for the App pane**: the Daemon already has the Workspace in reach; one inotify watch per shown file costs nothing and reports within a frame.

## Consequences

- Image rebuild (the Daemon gains `/fs/app`, `fs/watch` and the briefing text); a Sandbox on an older Daemon answers 404 to `/fs/app` ("cannot load (404)" on the card) and "method not found" to the watch, which the pane ignores (Reload works).
- `MediaKind` gains `"html"`; every switch over it and over `PreviewKind` was extended, and `.html`/`.htm` left the text-preview list.
- A page that used to make API calls from an `Origin: null` context (a `file://` page, a sandboxed extension frame) now gets 403; none is known.
- The CDN allowlist is global, not per Session: one setting, one CSP string, read on each request.
- Verified: typecheck, build, `test:attachments` (the raw route hands `.html` out as an attachment, the app route carries the CSP and refuses 16 MiB + 1), `test:auth` (`Origin: null` is 403 on `/sessions`, passes to authentication on the two file routes, real origins unchanged); in the browser, a Session whose Agent wrote `game.html` (canvas animation plus Chart.js from jsDelivr) shows it animating inline, Fullscreen, the App pane following saves, `fetch('/api/sessions')` refused by `connect-src 'none'`, `window.origin === "null"` in a tab of its own, no text preview.
